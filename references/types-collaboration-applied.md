# 合作、研发与应用项目的写法

## 国际与多方合作：能力互补必须落实到任务

先沿用主项目文体，再补充合作逻辑：共同问题 → 各方已有能力及不足 → 互补接口 → 分工与交付 → 联合验证。

P11页13将两方技术能力、既有共同结果和未解决限制放在同一论证中；页33–35先交代课题之间的输入输出和反馈，再列双方分工及年度安排。按这种方式写清“谁提供什么、另一方如何使用、在哪里汇合”。交流次数、对方声望和机构简介不能替代合作必要性。

真正并行的任务不强行串成前后依赖。共享样品、数据口径、共同判据等仅在用户有依据时写成已约定内容；尚未商定的安排标为建议，不能伪造合作承诺。

## 重点研发与任务牵引项目：技术瓶颈可以成为主问题

围绕场景需求和指南目标展开，写明现有方案在哪个工况、规模或环节不能满足要求。技术问题不必硬改成基础科学问题；需要机制研究时说明它服务于哪个关键决策。

任务描述包含适当层次的对象、关键技术、任务接口和可验证输出。总体指标应分解到任务，并有集成测试收束；避免子任务各自成功而系统目标无法验证。研发、集成、样机测试和应用示范分别表述，不相互替代。

P07已纳入全文阅读：页17分别列出科学问题与关键技术，页18列考核条件和评测方式，页35–37组织相互关联的任务。这支持“重点研发＋国际合作”的组合选择；不能仅凭“重点研发”四字预设其所有指标、成熟度和组织要求。

## 应用转化与地方/企业研发：写清使用条件与交付状态

P06页10–11将装置、组件、材料和系列产品分别组织任务，页16把核心参数与交付对象列入考核。可迁移的是“对象—性能—条件—验证”的写法，具体安全阈值、测试标准、市场规模和经济数据均不得迁移。

- 需求用具体使用情境解释；比较对象、性能条件和尺度保持一致。
- 指标写单位、工况、基线和测试方法；未提供数值时留缺口，不用“国际领先”填补。
- 实验室结果、样机性能、中试能力、产业化和实际销售分别陈述。
- 经济预测说明输入假设与测算关系；不得把预测收入当成已实现收入。
- 风险分析紧扣关键失效环节及替代路径，不为了齐全添加不相干清单。

## 进展、结题与执行计划

进展报告先说明本期完成的任务，再展示数据、比较和解释，最后交代偏差、问题与后续工作。P09正文1.2–1.3、P23页1–2提供“实际动作—观测结果—解释”的例子；原文解释仍需证据支持，不能照抄成已确立机制。

结题报告围绕批准目标对照完成情况，区分完成、部分完成和调整。未提供完成证据时不得默认“全部完成”。计划书按批准任务组织执行；P12/P24缺少完整立项论证，不能据此学习项目提出方式。

阶段报告中的已完成语态不用于申请书的预期成果；申请书中的计划语态不掩盖结题缺口。
