# 质量检查

按本次任务范围检查，不把全文流程强加给一句润色。

## 必须通过

- 数据、引用、团队能力、合作条件和成果归属有依据；不能把样本事实带入用户项目。
- 事实、推断、假设、计划和预期彼此可区分，计划不写成已完成。
- 技术含义、数字、条件、引文和用户锁定内容在修改后保真。
- 当前指南/用户要求优先于历史范本；申请、执行、进展和结题的任务不混淆。

## 类型适配

| 类型 | 核查重点 |
|---|---|
| 青年/面上基础研究 | 问题聚焦，假设或研究切口有依据，任务范围与证据匹配 |
| 重点/重大基础研究 | 子问题为何需要共同研究，输入输出与综合认识是否清楚 |
| 人才 | 个人贡献与团队成果区分，研究主线连续，未来计划有新增问题 |
| 合作叠加 | 互补性落实到任务与交接；不把交流活动当研究成果 |
| 研发/应用 | 指标条件、对照基线、任务集成和交付验证可落实 |
| 进展/结题 | 对照批准目标，有实际证据，不把计划复制成完成情况 |

## 逻辑与语言

- 关键判断有直接支持；相关性和拟合结果未被夸大成因果机制。
- 显著性检验、模型拟合/预测、参数优化与机制验证分别陈述；统计检验超过临界值不能直接推出已找到性能最优结构，也不能证明因果机制。
- 跨材料或跨场景的数值比较核对温度、压力、湿度、厚度、密度和测量方式等必要条件；正文不同位置出现的温度和性能数值不能未经核实拼成同一工况结论。
- 每段中心任务明确，但不强求每段都包含对象、变量、方法和落点。
- 段落转折有具体限制，段末结论由前文支持，无突然增加的概念。
- 术语准确且一致；主语、指代与并列层级清楚。
- 相邻段落开头和结尾没有机械复制；长句的每个分句都有必要信息。
- 具体内容、目标、问题、方案和创新各司其职，允许必要关键词复现。
- 不凭“缺少三点创新”“不是长复句”“没有机制动词”判为不合格。

## 引用与证据

引文放在它直接支持的论断之后；原始研究优先支持具体机制，综述支持背景。图表和自有结果不能被无关外部文献替代。用户仅要求引用处理时不顺改正文。引用唯一性和编号顺序按用户要求，不能为编号方便错配证据。

“首次、普适、领先”等须有比较范围与依据；当期资料并不自动验证旧范本的科学判断。强断言证据不足则限定、删除或列为待核实，不能自行补造检索结论。

## 验证新规则

用相同事实底稿进行改写或跨类型试写，检查是否保持事实、改变的是论证重心、输出能否完成用户任务。没有独立评阅时明确是自检，不称盲评；没有可比评分时不宣称提升百分比。规则结构校验不代表写作质量已经得到用户认可。
